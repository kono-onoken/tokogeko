# とうげこう（登下校管理アプリ）

Tokyo Community School の登下校を、iPad で子ども自身が記録するためのアプリです。
顔写真つきで登校・下校を記録し、Google スプレッドシート／ドライブに保存します。

- 画面（フロント）：PWA（素の HTML/CSS/JS）。GitHub Pages で公開
- 記録（バックエンド）：Google Apps Script（API 専用）＋ スプレッドシート ＋ ドライブ
- 詳しい仕様は [CLAUDE.md](CLAUDE.md) を参照

```
iPad ×3 ──→ Webアプリ（docs/） ──fetch──→ GAS（gas/） ──→ スプレッドシート／ドライブ
```

## フォルダ構成

| パス | 内容 |
|---|---|
| `CLAUDE.md` | 仕様書 |
| `gas/` | Google Apps Script（`Code.gs`、`appsscript.json`） |
| `docs/` | GitHub Pages で公開するフロント一式（`index.html`、`sw.js`、`manifest.webmanifest`、`icons/`） |
| `tools/` | 開発用（公開されない）：`dev-server.js`（ローカルサーバー＋モックAPI）、`check-api.sh`（本物の GAS の確認）、`make-icons.js`（アイコン生成） |

## 注意（絶対にコミットしないもの）

- GAS のウェブアプリ URL
- 合言葉（`API_TOKEN`）
- スプレッドシート ID、ドライブのフォルダ ID
- `gas/.clasp.json`（scriptId を含む）

これらは GAS のスクリプトプロパティ、または iPad 内（localStorage）にだけ保存します。

## 1. 事前準備（人間の作業）

学校の Google アカウントで次を用意します。

1. **写真用フォルダ**（ドライブ）を作る。共有は**スタッフだけ**にし、「リンクを知っている全員」は絶対にオンにしない。
2. **アプリ用スプレッドシート**を作る（名前は自由。例：「TCS登下校管理」）。GAS は、このスプレッドシートに**バインド**（紐づけ）して使う。
3. **合言葉（API_TOKEN）** を作る。ターミナルで次を実行し、出てきた文字列を控える（他人に見せない・コミットしない）。
   ```bash
   openssl rand -hex 24
   ```
4. clasp にログインする（済んでいれば不要）。
   ```bash
   clasp login
   ```

ID の調べ方：

| 値 | 見つけ方 |
|---|---|
| アプリ用スプレッドシートの ID（`clasp` でバインドするときに使う） | スプレッドシートの URL `https://docs.google.com/spreadsheets/d/`**ここ**`/edit` |
| `FOLDER_ID` | フォルダの URL `https://drive.google.com/drive/folders/`**ここ**`?usp=sharing` |
| `ATTENDANCE_BOOK_ID`（照合機能で使う。あとで設定） | 出席簿スプレッドシートの URL の同じ位置 |

> `APP_SHEET_ID`（アプリ用スプレッドシートの ID）は、`setup()` が自動で保存するので、手で設定しない。

> `clasp` が `invalid_grant … invalid_rapt` と出したら、Google の再ログインが必要。`clasp login` をやり直す（一定時間ごとに求められる）。

## 2. GAS のセットアップとデプロイ

### 2-1. コードを GAS に送る（clasp）

`gas/.clasp.json` に scriptId と、バインド先のスプレッドシートの ID が入っている（コミットされない）。コードを直したら次で反映する。

```bash
cd gas
clasp push
```

**バインドスクリプトを新しく作る場合**（ゼロから作る場合・作り直す場合）

作業用の空のフォルダで、`--parentId` にアプリ用スプレッドシートの ID を指定して実行する。

```bash
mkdir /tmp/bind && cd /tmp/bind
clasp create-script --parentId <アプリ用スプレッドシートのID> --title "とうげこう API"
```

- 「Bound to document: …」と出れば成功。**`--type sheets` は付けない**（付けると、指定したスプレッドシートではなく、**新しい空のスプレッドシート**が作られてしまう）。
- できた `.clasp.json` を `gas/.clasp.json` にコピーし、`gas/` で `clasp push -f`（作成時に `appsscript.json` が初期値で作られるため、`-f` で手元の版に置き換える）。

GAS のエディタを開く：

```bash
cd gas
clasp open-script
```

> **古い standalone 版**（段階2で作った版）の `.clasp.json` は、`gas/.clasp.standalone.json` に控えてある。移行が終わるまで、**古いデプロイは止めない**（2-7）。

### 2-2. スクリプトプロパティを設定する

エディタ左の「プロジェクトの設定」（歯車）→ 下の「スクリプト プロパティ」→「スクリプト プロパティを編集」で追加して保存する。

| プロパティ | 値 | 必須 |
|---|---|---|
| `FOLDER_ID` | 写真フォルダの ID | 必須 |
| `API_TOKEN` | 合言葉（iPad の設定画面に入れるものと**同じ**もの） | 必須 |
| `ATTENDANCE_BOOK_ID` | 出席簿スプレッドシートの ID | 照合機能で使う（あとで） |
| `SLACK_WEBHOOK_URL` | Slack の Incoming Webhook の URL | 任意（未設定でもよい） |
| `APP_SHEET_ID` | （`setup()` が自動で保存する） | 手で入れない |

> 古い standalone 版で使っていた `FOLDER_ID` と `API_TOKEN` は、**同じ値**を入れる。そうすれば、iPad の合言葉を変えなくて済む。

### 2-3. `setup()` を実行する

1. エディタ上部の関数選択で `setup` を選び「実行」。
2. 初回は権限の承認を求められる（「詳細」→「（安全ではないページ）に移動」→ 許可）。スプレッドシート、ドライブ、外部サービスへの接続（Slack 用）、メニューの表示の許可が出る。
3. 下の実行ログに、次のように出れば OK。
   - `APP_SHEET_ID を保存しました。`
   - `シートを確認しました: …`
   - 写真フォルダを確認しました（共有設定: **PRIVATE**）
   - 共有設定が PRIVATE 以外なら【注意】が出る。フォルダの共有を見直すこと。
   - 名簿の見出しが足りないと、【注意】で足りない列が出る（「担任」列がないときなど）。
4. スプレッドシートに、次のシートができている。**すでにあるシートのデータや見出しは書き換えない。**

   | シート | 内容 |
   |---|---|
   | 名簿 | 人が管理。列：A:児童ID（6桁）、B:名前、C:よみ、D:学年、E:担任、F:在籍(TRUE/FALSE)、G:並び順 |
   | 担任 | 担任名と Slack メンバーID |
   | 記録 | アプリが追記する（登下校の記録） |
   | 照合設定 | 照合の基準（締切の時刻など）。初期値が入る |
   | 例外日 | 行事・短縮日課の日の設定（任意） |
   | 照合結果・Slack下書き | 照合機能が使う（照合機能を実装したあとに使う） |

5. 「名簿」に児童を入力する。**児童ID は、出席簿の A 列と同じ 6桁のID** にする（照合のキー）。
   - 列の順番は、**見出しの名前**で判断する。見出し（`児童ID`・`名前`・`よみ`・`学年`・`担任`・`在籍`・`並び順`）は変えない。
   - 動作確認だけ先にしたいときは、関数 `addSampleRoster` を実行すると、ダミーの6名（児童ID `900001`〜`900006`、各学年1名）が入る。**確認が済んだら削除する。**

### 名簿の書き方（漢字とふりがな）

名前は、1年生から**漢字で**表示する（自分の名前を理解するため）。1・2年のグループでは、「よみ」がふりがなとして漢字の上に付く。3年生以上はふりがななし。

| 列 | 書き方 | 例 |
|---|---|---|
| 名前 | **漢字**で書く。姓と名のあいだにスペースを入れる | `小野 健` |
| よみ | **ひらがな**で書く。名前と同じ位置にスペースを入れる | `おの けん` |

- 姓と名の数が名前とよみで同じなら、**姓・名それぞれの上に**ふりがなが付く（`<ruby>小野<rt>おの</rt></ruby> <ruby>健<rt>けん</rt></ruby>`）。スペースの数が合わないときは、名前全体の上に付く。
- ひらがなだけの部分（例：名が「けん」）にはふりがなを付けない。
- 画面の文言（「登校」「下校」「下校済み」「戻る」など）も、**全学年で漢字**。1・2年のグループでは、文言にもふりがなが付く。3年生以上はふりがななし。

### 2-4. ウェブアプリとしてデプロイする（初回のみ）

> 2-3 の `setup()` を**先に**実行して、権限の承認を済ませておく。承認していないと、ウェブアプリが認可エラーで動かない。スコープを追加したときも、エディタで一度関数を実行して承認し直してからデプロイを更新する。

1. エディタ右上「デプロイ」→「新しいデプロイ」。
2. 歯車 →「ウェブアプリ」を選ぶ。
3. 設定：
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**
4. 「デプロイ」→ 表示される **ウェブアプリの URL**（`https://script.google.com/macros/s/…/exec`）と、「デプロイを管理」にある **デプロイ ID** を控える。
   - この URL は iPad の設定画面に入力する（コミットしない）。

### 2-5. curl で動作を確認する

ターミナルで、URL と合言葉を環境変数に入れる（履歴に残したくなければ `read -s` を使う）。

```bash
export GAS_URL='https://script.google.com/macros/s/xxxxxxxx/exec'
read -s TOKEN && export TOKEN   # 合言葉を貼り付けて Enter
```

**名簿（roster）**：`group` は `12`（1・2年）/ `34`（3・4年）/ `56`（5・6年）。

```bash
curl -sL "$GAS_URL?action=roster&group=12&token=$TOKEN"
```

→ `{"ok":true,"group":"12","children":[…]}` で、該当学年の在籍児童だけが返る。

**今日の状態（today）**

```bash
curl -sL "$GAS_URL?action=today&group=12&token=$TOKEN"
```

→ 全員 `"status":"未登校"` から始まる。

**誤った合言葉**

```bash
curl -sL "$GAS_URL?action=roster&group=12&token=wrong"
```

→ `{"ok":false,"error":"unauthorized"}`

**記録の送信（POST）**：任意の JPEG 写真（`photo.jpg`）を使う。児童 ID は名簿にあるもの（ダミーなら `900001`）。

> 手早く確認するなら、`tools/check-api.sh`（URL と合言葉を聞かれる）が、名簿の先頭の児童で、同じ確認を自動で行う。

```bash
IMG=$(base64 < photo.jpg | tr -d '\n')
RID=$(uuidgen)
printf '{"token":"%s","recordId":"%s","childId":"900001","type":"登校","capturedAt":"%s","group":"12","resent":false,"imageBase64":"data:image/jpeg;base64,%s"}' \
  "$TOKEN" "$RID" "$(date '+%Y-%m-%d %H:%M:%S')" "$IMG" > /tmp/post.json

curl -sL -H 'Content-Type: text/plain' --data-binary @/tmp/post.json "$GAS_URL"
```

→ `{"ok":true}`。確認すること：
- 「記録」シートに1行増えた（撮影日時・受信日時は文字列のまま）
- 写真フォルダに今日の日付のサブフォルダができ、`HHmmss_900001_…_登校.jpg` が入っている
- 手順の `today` を再度実行すると、900001 が `"登校中"` になる

**同じ記録をもう一度送る（二重記録されないこと）**

```bash
curl -sL -H 'Content-Type: text/plain' --data-binary @/tmp/post.json "$GAS_URL"
```

→ `{"ok":true,"duplicate":true}`。記録シートは1行のまま。

確認後は `rm /tmp/post.json` で消し、ダミーの行・写真は削除する。

**エラーの例**

| `error` | 意味 |
|---|---|
| `unauthorized` | 合言葉が違う |
| `invalid_group` / `invalid_type` / `invalid_captured_at` / `invalid_record_id` / `invalid_image` | 送った値の形式が違う |
| `unknown_child` | 名簿にない児童 ID |
| `busy` | 同時書き込みで30秒待っても順番が来なかった（再送すれば通る） |
| `server_error` | GAS 側の失敗（エディタの「実行数」でログを見る。`setup()` 未実行やプロパティ未設定が多い） |

### 2-6. 古い写真の削除（手動）

学期末などに、指定日**より前**の日付フォルダをドライブのゴミ箱へ移せる（30日間は復元可）。
エディタで `runDeleteOldPhotos` の `deleteOldPhotos('')` の日付（例：`'2027-04-01'`）を入れ、`clasp push` してから `runDeleteOldPhotos` を実行する。実行後は日付を空に戻しておく。

### GAS 更新時の注意

コードを修正したら「デプロイを管理」→ 既存のデプロイを編集 →「新しいバージョン」で更新します。
**新しいデプロイを作ると URL が変わり、iPad からつながらなくなります。**

clasp を使う場合は、先に `clasp push` でコードを送ってから、既存のデプロイ ID を指定して更新します（`-i` を付け忘れると新しいデプロイができて URL が変わるので注意）。

```bash
cd gas
clasp push
clasp deploy -i <deploymentId>
```

### 2-7. 古い standalone 版からの移行（iPad の URL の差し替え）

バインド型は、standalone とは**別のプロジェクト**なので、デプロイすると**新しい URL** になる。URL は変わるが、iPad の合言葉・暗証番号・端末内のデータは、そのまま使える。

1. 新しいバインド型で、2-2〜2-5 を済ませ、新しい URL で動作を確認する。**古い standalone のデプロイは、止めずに残す**（iPad は、古い URL のまま動き続ける）。
2. **下校後や休日**に、3台の iPad を順に切り替える。
   1. 画面左下に「未送信」が出ていない（0件）ことを確認する。残っていたら、設定画面の「いま再送」で送り切る。
   2. 右上の隅を3秒長押し → 暗証番号 → 設定画面。
   3. 「GAS のウェブアプリ URL」を**新しい URL** に書き換える（合言葉は、同じ値ならそのまま）。
   4. 「接続テスト」→「つながりました」→「保存」。
3. 3台とも新しい URL で動くことを確認してから、古い standalone のデプロイを停止する（「デプロイを管理」→ アーカイブ。プロジェクト自体は、1か月ほど残して戻せるようにしておく）。
4. そのあと、名簿を新しい並び（担任列つき・6桁ID）にする。**古い GAS は、古い並びを前提に名簿を読む**ため、名簿の並びを変えるのは、必ず iPad の URL を差し替えたあとにする。

## 3. フロントの動作確認（ローカル）

カメラには HTTPS が必要だが、`localhost` だけは HTTP でも使える。ローカル確認は必ず `localhost` で行う（`192.168.…` などの IP アドレスではカメラが使えない）。

### 3-1. モック GAS つきのローカルサーバー（本物の GAS なしで試す）

```bash
cd /Users/tcsstaff/Documents/Claude/tokogeko-app
node tools/dev-server.js
```

| 何が動くか | URL |
|---|---|
| アプリ本体（`docs/`） | http://localhost:8080 |
| GAS の代わりのモック API | http://localhost:8787/exec |

アプリの設定画面（初回は自動で開く）に次を入れて保存する。

| 項目 | 値 |
|---|---|
| 学年グループ | 好きなもの（`34` は14人、`12` は5人のダミー児童） |
| URL | `http://localhost:8787/exec` |
| 合言葉 | `test-token` |
| 暗証番号 | 好きな4〜6桁 |

モックの記録はメモリ上だけ（写真は保存しない）。サーバーを止めると消える。`http://localhost:8787/__records` で受信した記録を見られる。止めるときは `Ctrl+C`。

### 3-2. 本物の GAS につないで試す

同じ `http://localhost:8080` の設定画面に、本物のウェブアプリ URL と合言葉を入れる（ダミー名簿を入れておくと確認しやすい）。`node tools/dev-server.js` は、アプリを配信するためにだけ使う。

### 3-3. 確認すること（チェックリストの一部）

| 確認 | やり方 |
|---|---|
| 一覧・状態表示 | 名前を押して撮影 → タイルが緑（登校中・顔写真つき）→ もう一度 → 青灰色（下校済み・写真が薄い） |
| 下校済みの子 | タップすると「もう下校しているよ」だけ出て、カメラは起動しない |
| 暗証番号 | 画面右上の隅を3秒長押し → 暗証番号 → 設定画面（短く押しても開かない） |
| オフライン | 下記 |
| 日付が変わる | 翌日になると全員が未登校に戻り、前日の表示用写真は消える |
| 30秒放置 | 撮影画面で30秒触らないとホームに戻り、カメラが止まる |

**オフラインの確認**

1. Chrome の開発者ツール →「Network」→ スロットリングを「Offline」にする（またはモックサーバーを `Ctrl+C` で止める）。
2. 名前を押して撮影する。すぐに「登校中」になり、左下に「未送信 1件」が出る。
3. そのままページを再読み込みする（Service Worker があるので、サーバーが止まっていても起動する）。一覧・状態・「未送信 1件」が残っている。
4. 「Offline」を戻す（モックを再起動する）。`online` イベントか60秒以内に自動で送信され、「未送信」が消える。
5. 送信された記録は `resent: true` で、撮影日時はオフラインで撮った時刻のまま。

**Service Worker の更新**

`docs/sw.js` の `CACHE`（例：`tokogeko-v3`）は、アプリ本体を変更して公開するたびにバージョン番号を上げる。上げないと、iPad に古い画面がキャッシュされたまま残る。更新は「次に起動したとき」に反映される（アプリを一度完全に閉じて開き直す）。表示はホーム画面の右下の小さな `v3` で確認でき、`docs/index.html` の `APP_VERSION` も合わせて更新する。

## 4. 公開（GitHub Pages）

`docs/` フォルダを GitHub Pages で公開する。公開されるのはアプリの画面（`docs/`）だけでなく、リポジトリ全体が見える（無料プランでは**公開リポジトリ**が必要）。URL・合言葉・各種 ID・`.clasp.json` はコミットされないようにしてあるので、リポジトリの中身が公開されても、記録や写真は見られない。

> 無料の GitHub では、Pages は公開リポジトリだけで使える。非公開のままにしたい場合は、GitHub の有料プラン（Pro / Team）が必要。

### 4-1. コミット前の確認（済み）

```bash
git add -A -n          # コミット対象の一覧（.clasp.json が入っていないこと）
git check-ignore -v gas/.clasp.json
```

### 4-2. GitHub にリポジトリを作る

1. https://github.com/new を開く。
2. Repository name：`tokogeko`（好きな名前でよい。以下この名前で説明）。
3. **Public** を選ぶ。
4. 「Add a README file」「.gitignore」「license」は**すべてオフ**のまま（すでにあるため）。
5. 「Create repository」。

### 4-3. 初回コミットと push

ターミナルで次を実行する（名前・メール・ユーザー名は自分のものに置き換える）。

```bash
cd /Users/tcsstaff/Documents/Claude/tokogeko-app
git config user.name "あなたの名前"
git config user.email "GitHub に登録しているメール"
git add -A
git commit -m "とうげこう: 初回コミット"
git remote add origin https://github.com/<ユーザー名>/tokogeko.git
git push -u origin main
```

- push のとき、パスワードを聞かれたら、GitHub のパスワードではなく **Personal Access Token** を使う（GitHub → Settings → Developer settings → Personal access tokens → 「repo」権限）。ブラウザでのログインを求められた場合は、その画面に従う。
- ターミナルが苦手なら、GitHub Desktop（「Add Local Repository」→ Publish repository）でも同じことができる。

### 4-4. Pages を有効にする

1. GitHub のリポジトリ →「Settings」→ 左の「Pages」。
2. 「Build and deployment」の Source を **Deploy from a branch** にする。
3. Branch を **`main`**、フォルダを **`/docs`** にして「Save」。
4. 1〜2分待つと、画面の上に公開 URL が出る：`https://<ユーザー名>.github.io/tokogeko/`
   - このプロジェクトの公開 URL：**https://kono-onoken.github.io/tokogeko/**

### 4-5. 公開 URL での確認

公開 URL を Chrome で開いて確認する（HTTPS なので、カメラも Service Worker も使える）。

- 初回は設定画面が開く → 本物のウェブアプリ URL と合言葉を入れて接続テスト → 保存。
- 撮影して記録される（記録シートの行、写真フォルダ）。
- 開発者ツール →「Application」→「Service Workers」に `sw.js` が「activated」で出る。「Cache Storage」に `tokogeko-v3`（など）が出る。
- 機内モード相当（Network を Offline）で再読み込みしても起動する。

> 公開 URL では、`localhost` とは別のサイトとして扱われるため、設定（URL・合言葉・暗証番号）は入れ直しになる。iPad でも同じ。

### 4-6. アプリを更新するとき

1. `docs/` の中身を直したら、`docs/sw.js` の `CACHE`（例：`tokogeko-v3` → `v4`）と、`docs/index.html` の `APP_VERSION`（`v3` → `v4`）のバージョン番号を上げる。
2. `git add -A && git commit -m "…" && git push`
3. 1〜2分で公開が更新される。iPad は、アプリを一度完全に閉じて開き直す（2回開き直すと確実）と、新しい版になる。右下の小さなバージョン表示で確認できる。

## 5. iPad のセットアップ

iPad は3台。どれも同じアプリ（同じ URL）で、**学年グループの設定だけが違う**。

| 端末 | 学年グループ | ラベル（iPad の裏などに貼る） |
|---|---|---|
| iPad A | 1・2年 | `1・2年` |
| iPad B | 3・4年 | `3・4年` |
| iPad C | 5・6年 | `5・6年` |

> 画面の名称は iPadOS のバージョンで少し違う。この手順は iPadOS 17〜18 を想定している。実機で名前が違うときは、近い項目を探す。

### 5-0. 用意するもの

- 校内の Wi-Fi（iPad 3台とも接続済み）
- **GAS のウェブアプリ URL**（`https://script.google.com/macros/s/…/exec`）と**合言葉**（`API_TOKEN`）。本人だけが見られる場所（パスワード管理アプリなど）に控えておき、メールやチャットに貼らない。
- 暗証番号（4〜6桁）を1つ決めておく（3台で同じでも、別々でもよい）。
- 設置場所（スタンドなど）と充電ケーブル。

### 5-1. ホーム画面に追加する（3台とも）

1. **Safari** で、次の URL を開く（AirDrop・メッセージなどで URL を送ると楽）。
   ```
   https://kono-onoken.github.io/tokogeko/
   ```
   ※ Chrome など Safari 以外では、「ホーム画面に追加」で全画面にならないことがある。必ず Safari を使う。
2. 画面上部の **共有ボタン**（四角から上向きの矢印）→ **「ホーム画面に追加」**。
3. 名前は「とうげこう」のまま。「**Web アプリとして開く**」のスイッチが出たら**オン**にして、「追加」。
4. Safari を閉じる。**これ以降は、ホーム画面の「とうげこう」アイコンから起動する。**

> **重要**：ホーム画面から起動するアプリは、Safari とは**別の保存領域**を使う。設定（URL・合言葉・暗証番号）や未送信の記録は、**ホーム画面のアプリ側**に入れる。Safari で先に設定していても、引き継がれない。

### 5-2. 初回設定（3台とも）

1. ホーム画面の「とうげこう」を起動する。初回は、設定画面が自動で開く。
2. 次を入力する。

   | 項目 | 入れるもの |
   |---|---|
   | 学年グループ | iPad A=1・2年 / iPad B=3・4年 / iPad C=5・6年 |
   | GAS のウェブアプリ URL | 5-0 で控えた URL |
   | 合言葉 | 5-0 で控えた合言葉 |
   | 暗証番号 | 4〜6桁の数字 |

3. 「**接続テスト**」→「つながりました（○年：n人）」と出ることを確認する。
4. 「**保存**」→「保存しました（名簿 n人）」。
5. 「とじる」で名前一覧に戻る。そのグループの児童だけが、学年ごとに並ぶ。

> 暗証番号は、保存すると**ハッシュ化**されて端末に残り、あとから見られない。忘れたら、5-8 の「設定のやり直し」が必要。

### 5-3. カメラの許可

1. 名前を1つ押して、撮影画面を開く。
2. 「"とうげこう" がカメラへのアクセスを求めています」と出たら、**「許可」**。
3. 自分の顔が映ることを確認して、**「もどる」**を押す（撮影ボタンは押さない）。

> **注意**：iPad のホーム画面アプリでは、**アプリを起動し直すたびに**カメラの許可を聞かれることがある（iPadOS の仕様。バージョンで違う）。そのため、毎朝の運用に「カメラの許可」の手順を入れてある（第6章）。「設定」→「Safari」→「カメラ」を「許可」にすると、聞かれなくなることもあるが、効くかどうかはバージョン次第なので、実機で確かめる。

### 5-4. 自動ロックを「なし」にする（3台とも）

1. 「設定」→「画面表示と明るさ」→「**自動ロック**」→「**なし**」。
2. 運用中は**充電したまま**使う（充電器につないだままスタンドに置く）。

### 5-5. 通知を止める（おすすめ）

通知のバナーが画面に出ると、子どもが触ってしまう。「設定」→「集中モード」→「おやすみモード」を、授業時間のあいだオンにするか、「通知」で不要なアプリの通知を切る。

### 5-6. アクセスガイドの設定（3台とも）

**アクセスガイド**は、1つのアプリだけを使わせて、ホームに戻れなくする iPad の機能。子どもが他のアプリを開かないようにする。

**設定（最初に1回）**

1. 「設定」→「アクセシビリティ」→「**アクセスガイド**」→ **オン**。
2. 「**パスコード設定**」→「アクセスガイドのパスコードを設定」→ 4桁以上の数字を2回入力する。
   - これは、アプリの暗証番号とは**別のもの**（アクセスガイドを終了するときの番号）。先生だけが知る番号にして、控えておく。
3. 「Face ID（または Touch ID）」はオフにしておく（顔認証で終了できてしまうため）。
4. 「**ショートカット**」（またはアクセシビリティのショートカット）で「**アクセスガイド**」を選ぶ。→ トップボタン（ホームボタンの iPad ではホームボタン）を**3回押す**と開始できる。
5. 「タイムリミット」はオフのまま。

**開始する**

1. 「とうげこう」を起動して、名前一覧が出ている状態にする。
2. トップボタン（またはホームボタン）を**すばやく3回**押す。
3. 左下の「**オプション**」を開いて、次のとおりにする。

   | オプション | 設定 |
   |---|---|
   | サイドボタン（トップボタン） | オフ |
   | 音量ボタン | オフ |
   | 動き | 画面を縦横に回したいなら**オン**／向きを固定したいなら**オフ** |
   | キーボード | オフ |
   | タッチ | **オン**（オフにすると、画面が押せなくなる） |
   | 時間制限 | オフ |

4. 「完了」→「**開始**」。画面の下に「アクセスガイド開始」と出て、ホーム画面に戻れなくなる。

**終了する**

1. トップボタン（またはホームボタン）を**3回**押す。
2. アクセスガイドの**パスコード**を入力して、左上の「**終了**」。

> 設定画面（右上の隅の3秒長押し）は、アクセスガイド中でも開ける（アプリの機能なので）。ただし、暗証番号が必要。

### 5-7. 設置と最終確認

1. iPad を、子どもの顔がインカメラに映る高さと向きに置く（スタンドなど）。
2. 次を確認する（1台ごと）。
   - 日付と時計が合っている（画面の左上に表示される。時刻は **iPad の時計**を使うので、「設定」→「一般」→「日付と時刻」→「自動設定」をオンにする）。
   - 名前一覧が、**その iPad のグループの児童だけ**である。
   - **自分（先生）の名前、またはテスト用の児童**で、「登校」→「下校」を撮影できる。タイルが緑→青灰色に変わる。
   - スプレッドシートの「記録」に行が増え、写真が日付フォルダに入っている。確認したら、テスト行・テスト写真を削除する。
   - 機内モードで撮影 →「未送信 1件」→ 機内モードを解除 → 数分以内に「未送信」が消える。
   - 全画面（アドレスバーがない）で表示されている。

### 5-8. 設定のやり直し

暗証番号を忘れた、グループを間違えた、などのとき。

- グループ・URL・合言葉の変更：設定画面を開けるなら、そこで直して「保存」。
- **暗証番号を忘れた場合**：ホーム画面の「とうげこう」を削除して、5-1 からやり直す。**削除すると、その iPad の「未送信の記録」と今日の顔写真も消える**。先に、Wi-Fi につないで「未送信 0件」になっていることを確認する。

## 6. 毎朝の運用

### 6-1. 朝（登校の前）

毎朝、先生が各 iPad で次を行う（3台とも）。

1. iPad の電源が入っていて、**充電器につながっている**ことを確認する。
2. **「とうげこう」を起動する**（ホーム画面のアイコン。前日からアプリが開いたままなら、一度アクセスガイドを終了して、アプリを閉じて開き直す）。
3. 画面を確認する。
   - 日付が**今日**で、グループが**その iPad のもの**である。
   - 全員が**グレー（未登校）**である。
   - 左下に赤い「**接続できません**」が出ていない（出ていたら Wi-Fi を確認する）。
   - 左下に「未送信 n件」が出ていない（出ていたら、設定画面で「いま再送」）。
4. **カメラの許可**：名前を**1つ押して**、「カメラへのアクセス」が出たら「**許可**」。顔が映ったら「**もどる**」を押す。
5. **アクセスガイドを開始**する（トップボタン3回 → 開始。5-6）。
6. iPad を設置場所に置く。

### 6-2. 登校・下校の時間

- 子どもが、自分の名前を押して、「登校」を押す。顔写真が撮れて、タイルが緑になる。
- 下校のときは、もう一度自分の名前を押して、「下校」を押す。タイルが青灰色になる。
- 押し間違えたときは「もどる」を押す。30秒触らないと、自動で名前一覧に戻る。
- 撮り直し・訂正は、先生が**スプレッドシートの「記録」**で行う。下校済みの子は、iPad からは撮影できない。

### 6-3. 夕方（下校のあと）

1. 全員が、**青灰色（下校済み）**になっているか見る。なっていない子は、先生がスプレッドシートで確認・訂正する。
2. 左下の「**未送信**」が消えている（0件）ことを確認する。残っていたら、Wi-Fi につないで、数分待つか、設定画面で「いま再送」。
3. アクセスガイドを終了して（トップボタン3回 → パスコード → 終了）、iPad を**充電**する。

### 6-4. 名簿を変えたとき

名簿シートを直した（児童の追加、在籍を FALSE にする、漢字・よみの修正など）あとは、各 iPad の設定画面（右上の隅を3秒長押し → 暗証番号）で「**名簿の再読み込み**」を押す。何もしなくても、起動時と30分ごとに自動で読み込まれる。

### 6-5. アプリを更新したあと

README 4-6 の手順で公開したあと、iPad のアプリを**一度完全に閉じて開き直す**（上にスワイプしてアプリを終了 → もう一度タップ。確実にするなら2回）。右下の小さな表示（`v3` など）が新しい版になる。更新のたびに、アクセスガイドは、終了して → 起動し直して → 開始し直す。

### 6-6. うまくいかないとき

| 症状 | 対処 |
|---|---|
| カメラが映らない／許可を聞かれない | アプリを一度閉じて開き直し、名前を押す。それでもだめなら、「設定」→「Safari」→「カメラ」を確認する。 |
| 「カメラが使えません」と出る | カメラの許可が「拒否」になっている。「設定」→「Safari」→「カメラ」を「許可」か「確認」にして、アプリを開き直す。 |
| 左下に赤い「接続できません」 | Wi-Fi を確認する。記録は端末に残っていて、つながれば自動で送られる。 |
| 「未送信」が減らない | 設定画面の未送信一覧で、エラーを見る。「合言葉がちがいます」なら、GAS 側の `API_TOKEN` を変えていないか確認し、設定の合言葉を直して「保存」。 |
| 名前が出ない／間違っている | 設定画面で「名簿の再読み込み」。それでも直らなければ、名簿シートの「在籍」「学年」を確認する。 |
| 日付が違う／時刻がおかしい | 「設定」→「一般」→「日付と時刻」→「自動設定」をオンにする。 |
| 古い画面のまま | アプリを完全に閉じて、2回開き直す。 |
| 設定画面に入れない | 右上の隅を、**3秒**押し続ける。暗証番号を忘れたら 5-8。 |
